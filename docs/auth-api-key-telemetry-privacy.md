# Authentication and API-key application telemetry privacy

This leaf is based on integrated backend `86a25a84224eb151c8fa8a25943405b910fe8bb9`, after the preceding telemetry and notifier privacy fixes. It changes explicit telemetry in `login.ts`, `request-code.ts` and `create-api-key.ts`. No real provider calls, credentials, exported spans or deployment were used.

Onboarding no longer JSON-serializes IP or carrier metadata into application spans. Existing validation-enabled flags remain, and successful metadata reads emit fixed boolean markers. The two explicit IP-fetch failure records now use a fresh fixed-message `IpFetcherServiceError` with the original critical severity and no attached IP. The original domain error is still returned to the caller; authentication and refusal decisions are unchanged.

Email-code requests record only a fixed operation instead of the email address and IP. The original values still reach their exact IP/login-identifier limiter keys and the email-code provider. Limiter refusals still stop provider dispatch, and provider results/errors retain their original identity. Existing blocked-country controls, coalescing and deliberately separate operational notifications are untouched.

API-key creation spans contain only started/success/error flags. They no longer inspect or record the caller's name, account identifier, scopes, requested expiry or generated public key ID. Name/scope/IP/rate validation, account limits, key generation, hash-only persistence and the one-time raw-key response are unchanged. The deliberate lifecycle audit remains intact: `auditApiKeyCreated` still receives the account, public key ID, validated scopes, expiry and rate limit. It receives neither the raw API key nor its hash. This distinguishes the existing security audit contract from general application tracing; the audit retention policy is outside this change.

Validation: **136 tests across seven reviewed suites** pass under Node 24 with the integration runner's fake `safeEnvironment`, network guard and Watchman disabled. New regressions cover successful and refused phone/device onboarding, exact OTP/carrier/IP/device inputs, same-owner bootstrap order, fixed private-error diagnostics, disabled carrier-validation fallback, existing-user login, limiter ordering, exact email dispatch and API-key persistence/audit behavior. Rejected scope arrays have a throwing `join` method to prove they are not serialized for telemetry before validation. Existing destination-country, collision, key-domain and lifecycle-audit tests remain green. All three TypeScript configurations, scoped ESLint and `git diff --check` pass.

This is a scoped application-boundary fix. The source audit also found independent adapter sinks in `services/ipfetcher/index.ts` (raw Axios error and attached IP) and `services/twilio.ts` (carrier SDK result and OTP-validation error). Those files are unchanged here and need their own provider-contract tests. The IP adapter's `UnknownIpFetcherServiceError` is also a sibling of `IpFetcherServiceError`, while login currently checks the latter with `instanceof`; this leaf preserves that existing authentication behavior. It does not claim all adapter telemetry, operational alerts, domain error propagation, historical records or collector retention are sanitized.
