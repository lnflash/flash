# Multi-channel notification and pre-registration privacy

This leaf is based on integrated backend `0d856f52fc81d49638bf3fad0cc5b6efbd4a3cbd`, after the preceding automatic argument/GraphQL/HTTP privacy boundaries and push-notification cleanup. It changes the separate email/SMS/WhatsApp notifier and the pre-registration helper only. No real credentials, provider requests, exported spans or deployments were used.

The notifier no longer logs recipient or sender addresses, provider account/message identifiers, message lengths, SDK error objects, provider error messages/details or response fields. Initialization, delivery success/refusal/failure and unsupported-method paths record fixed operation/outcome text. The WhatsApp template indicator remains a boolean; content variables and message bodies remain private. Caught exceptions are not inspected or stringified for diagnostics, including initialization and bridge-network failures.

Provider behavior is retained: Twilio receives the original credentials, sender/recipient, SMS content and WhatsApp prefix/template arguments; SendGrid receives the original API key and email payload; the WhatsApp bridge receives the original secret header and JSON body. Configuration selection, bridge response acceptance, timeout cleanup and true/false delivery decisions remain unchanged. This cleanup adds no retry, provider redirect policy or delivery guarantee.

The pre-registration helper previously copied arbitrary `body.schema_id` into an application span before validating the callback secret. It now records the fixed supported schema and closed outcomes. An invalid or missing callback key is rejected without reading payload fields, including fields implemented as throwing getters. Authorized validation, phone lookup, refusal errors, repository error identity and read-only behavior remain unchanged. The span metadata does not include the submitted schema, phone or callback key.

Validation: **68 tests across six reviewed suites** pass under Node 24 with the integration runner's fake `safeEnvironment`, network guard and Watchman disabled. Tests assert exact credential/body delivery to mocked providers, email/SMS/plain and template WhatsApp success, all provider failures, unavailable configuration, unknown methods, bridge acceptance/network/JSON failures, callback preauthorization non-inspection, schema refusal and existing Kratos route/validation behavior. All three TypeScript configurations, scoped ESLint and `git diff --check` pass.

This is a scoped source fix. It does not sanitize all application errors or explicit identity metadata elsewhere, remove historical telemetry, or establish production collector retention policy. Internal domain errors preserve their application identity; the helper does not add raw error diagnostics. The private request values are still sent to their intended providers as required for delivery.
